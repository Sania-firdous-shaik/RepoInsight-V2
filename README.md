# RepoInsight V2

Repository intelligence for public GitHub codebases. The backend uses FastAPI, PostgreSQL, Qdrant, CPU Sentence Transformers embeddings, Tree-sitter parsing, and Groq for grounded generation. The React client provides authentication, repository indexing status, code exploration, source citations, and AI documentation.

## Requirements

- Python 3.11+
- Node.js 20+
- Docker Desktop or Docker Engine with Compose
- A Groq API key and a model name available to your account for AI generation
- Internet access on first indexing to download the configured embedding model and clone public GitHub repositories

## Local setup

1. Copy `.env.example` to `.env`. Set unique `SECRET_KEY` and `JWT_SECRET_KEY` values, and set `GROQ_API_KEY` plus `GROQ_MODEL`. Keep `.env` private. `GROQ_MODEL` is intentionally not hardcoded; use a model currently available in your Groq account.
2. Start PostgreSQL, Qdrant, and Redis:

   ```bash
   docker compose up -d
   ```

3. Install and start the backend:

   ```bash
   cd backend
   cp ../.env .env
   python3.11 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   alembic upgrade head
   uvicorn app.main:app --reload --port 8000
   ```

The backend loads the root `.env` when started from the repository root. If running from `backend/`, copy or link your `.env` there, or set environment variables in the shell. Existing installations should run `alembic upgrade head` before starting the updated API; migration `0002_index_generation` adds a nullable active-generation pointer and does not clear PostgreSQL records or Qdrant collections.

4. In another terminal, install and start the frontend:

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

Open http://localhost:5173. Register an account using a password of at least 10 characters, then add a public GitHub URL. The workspace has Code Explorer (file browsing, source, explanation, and summary), AI Code Review for a selected source file or the full repository, repository/folder/file/module AI Summarization, AI Code Assistant, hybrid semantic search, architecture diagrams, documentation generation, repositories, and settings. Reviews validate model findings against indexed source line ranges, retain commit-bound history, and redact likely credential assignments from review context. Repository review jobs run in the background, batch small sibling files, and save progress so rate-limited jobs can resume. Set `REVIEW_AI_CONCURRENCY` (default `1`), `REVIEW_AI_MIN_INTERVAL_SECONDS` (default `2.5`), and the `REVIEW_AI_MAX_RETRIES`, `REVIEW_AI_BACKOFF_BASE_SECONDS`, `REVIEW_AI_MAX_RETRY_WAIT_SECONDS`, and `REVIEW_AI_RETRY_JITTER_SECONDS` values to tune the review queue. Indexing happens in a FastAPI background task; the workspace polls status.

5. Check service health at http://localhost:8000/health and API docs at http://localhost:8000/docs.

## Useful commands

```bash
cd frontend && npm run build
cd backend && python -m pytest
```

Set `VITE_API_URL` only if the API is not at `http://localhost:8000/api`. Never put Groq credentials in frontend variables. Indexing limits are controlled by `MAX_REPOSITORY_SIZE_MB`, `MAX_FILE_SIZE_MB`, and `MAX_FILES`.

## Current scope

The application supports public GitHub repositories only. It stores user accounts, repositories, conversations, messages, and generated documentation in PostgreSQL. Qdrant stores source chunks and metadata. Tree-sitter-aware chunking extracts symbols and source ranges, and retrieval combines dense, BM25-style lexical, exact identifier/path/endpoint matches, reciprocal-rank fusion, deduplication, and per-file diversity. Retrieval is repository and active-index-generation scoped, with legacy untagged points supported. Prompt context has a token budget and citation metadata is retained through answers and generated explanations. Indexing stages a new generation before switching the active pointer and leaves the previous generation available if staging fails. File and repository limits and credential-file exclusions are applied before embedding. The indexer never executes repository code.

File explanations are generated by section from indexed source and related evidence, with commit/generation-bound cache records. AI summaries use bounded representative retrieval and hierarchical file-to-module-to-repository synthesis; cached summaries are tied to the indexed commit and generation. Markdown responses render with sanitized HTML, and source citations appear as clickable file and line references. Semantic search, Q&A, documentation, and architecture generation use the same repository-scoped retrieval. Use `cd backend && .venv/bin/python scripts/evaluate_hastakala.py` to compare the original retrieval baseline with the upgraded ranking on an already indexed Hastakala project. Add `--include-generation` to call the configured Groq model and inspect citation coverage; this option incurs model usage. The benchmark is read-only.

Private repository OAuth, durable distributed indexing workers, incremental Git-diff indexing, full dependency graph extraction, generated diagram rendering, and full conversation history UI are not implemented yet. Repository acquisition runs in an in-process background task, so use a durable worker before production deployment. Set production secrets, TLS, rate limiting, database backups, and deployment-specific CORS before exposing the service publicly.
